# PickMe — помощник абитуриента РАНХиГС

Командный проект: Telegram-бот и API для ответов на вопросы о поступлении. Моя роль — Team Lead команды из пяти человек: спроектировал разделение запросов по типам, интеграцию источников данных и сервисов, распределял задачи и проводил code review.

## Задача и результат

Абитуриенты задают вопросы двух разных типов: «Какие документы нужны?» и «Сколько бюджетных мест на этой программе?». Первый требует ответа по текстовой базе знаний, второй — поиска точных полей в таблице программ. Один и тот же свободный LLM-ответ для обоих типов ненадёжен.

В репозитории реализован бот, который принимает вопрос в Telegram, передаёт его в FastAPI и выбирает одну из трёх веток:

1. `chitchat` — короткий разговорный ответ;
2. `rag` — семантический поиск по FAQ и глоссарию в Milvus, затем ответ LLM с найденным контекстом;
3. `sql` — извлечение фильтра из вопроса, запрос к PostgreSQL по программе и формирование ответа на основе найденных строк.

История диалога хранится в Redis. Скрипт загрузки переносит исходные таблицы программ, FAQ и терминов из XLSX в PostgreSQL и Milvus. Сервисы запускаются через Docker Compose.

**Проверяемый результат:** рабочая цепочка `Telegram → API → маршрутизация → источник данных → ответ`, отдельные сценарии для текстовых и структурированных данных, а также скрипты offline-оценки. В репозитории нет опубликованного итогового отчёта с численными метриками качества; поэтому точность или эффект для приёмной комиссии здесь не заявляются.

### Примеры из демонстрационного диалога

| Вопрос | Что показал бот |
| --- | --- |
| «Сколько бюджетных и платных мест на программе „Управление ESG-проектами“ в 2025 году?» | Ответил по структурированным данным: 10 бюджетных и 18 платных мест в демонстрационном снимке. |
| «А на этой программе что изучают?» после вопроса о «Ресторанном деле» | Сохранил контекст предыдущей реплики и ответил о той же программе. |
| «Какая завтра погода в Москве?» | Не стал выдавать прогноз без актуальных данных и вернул разговор к вопросам поступления. |

Это примеры поведения из сохранённых скриншотов, не независимая оценка точности. Значения мест относятся к снимку данных за 2025 год; перед реальным использованием их нужно сверить с актуальными правилами приёма.

## Архитектура и мой вклад

```text
Telegram (aiogram) → POST /ask (FastAPI) → router
                                         ├─ chitchat → LLM
                                         ├─ rag → embeddings → Milvus (FAQ, термины) → LLM
                                         └─ sql → фильтр → PostgreSQL → LLM
                                            ↓
                                       Redis: история диалога
```

- [Маршрутизация](app/services/router.py) возвращает `chitchat`, `rag` или `sql`; при ошибке классификации выбирается RAG-ветка.
- [Поиск](app/services/faq_service.py) использует multilingual Sentence Transformers и cosine similarity в двух коллекциях Milvus.
- [SQL-ветка](app/services/sql_service.py) разрешает только заранее перечисленные поля и передаёт значение фильтра параметром запроса: LLM не генерирует произвольный SQL.
- [Сборка ответа](app/services/response_builder.py) связывает ветки и историю; [API](app/api/routes.py) и [Telegram-бот](bot/tg_bot.py) отделены друг от друга.
- [Оценка](stats/README.md) включает сценарии для end-to-end ответов, retrieval (`Recall@5`, `MRR`) и диагностики SQL-ветки. Скрипты оценки присутствуют; таблицы результатов запуска не опубликованы.

В текущем коде поиск в RAG-ветке векторный. BM25 и слияния лексической и векторной выдачи в опубликованной реализации нет.

## Быстрый старт

Нужны Docker с Compose, токен Telegram-бота и ключ OpenRouter. Из корня репозитория:

```bash
cp .env.example .env
# Заполните BOT_TOKEN и добавьте OPENROUTER_API_KEY в .env
docker compose up -d --build
docker compose exec fastapi python -m scripts.ingest
curl http://localhost:8000/health
curl -X POST http://localhost:8000/ask \
  -H 'Content-Type: application/json' \
  -d '{"text":"Какие документы нужны для поступления?","user_id":1}'
```

Текущий [`llm_service.py`](app/services/llm_service.py) обращается к OpenRouter с моделью `openai/gpt-4o-mini`; переменная `GROQ_API_KEY` в шаблоне `.env.example` осталась от предыдущей интеграции и этим клиентом не используется. Данные из `data/*.xlsx` служат демонстрационным снимком; условия приёма и стоимость необходимо сверять с актуальным официальным источником.

## Ограничения

Работа требует внешнего LLM API, локально поднятых баз и загрузки модели эмбеддингов. Качество ответов зависит от полноты и даты исходных таблиц. Наличие скриптов оценки не означает, что измеренный результат уже опубликован. Для реального применения нужны обновление данных, мониторинг ошибок и проверка ответов на актуальных правилах приёма.
